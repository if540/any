數位發展部公布了新版「網站無障礙規範」（中華民國 115 年 5 月版）。<!-- TODO 發布前確認：實施日期。規範 PDF 內文沒有寫實施日，檔名為 1151130，非官方來源指 2026-11-30 生效。 -->這次改版最大的變化，是對照的國際標準從 WCAG 2.1 換成 WCAG 2.2。

這篇把 110 年 3 月版和 115 年 5 月版逐條比對，分成**新增、刪除、修改**三類說明。

## 一張表看懂差異

| 項目 | 110 年 3 月版 | 115 年 5 月版 |
| --- | --- | --- |
| 對照的 WCAG | 2.1 | 2.2 |
| 原則／指引 | 4／13 | 4／13（不變） |
| 成功準則編號 | 78 | 87 |
| 實際要符合的準則 | 78 | 86（4.1.1 已刪除） |
| A 級 | 30 | 31（+2，−1） |
| AA 級 | 20 | 24（+4） |
| AAA 級 | 28 | 31（+3） |

原本的 78 項中，除了刪除的 4.1.1，其餘 77 項有 26 項改了文字，51 項只有排版差異。

## 新增：9 項成功準則

新增的 9 項就是 WCAG 2.2 新增的準則，編號也相同。

| 編號 | 名稱 | 等級 | 一句話說明 |
| --- | --- | --- | --- |
| [2.4.11](/any/skills/2-4-11/) | 焦點不遮蔽(最小) | AA | 取得焦點的元件不能被完全擋住 |
| [2.4.12](/any/skills/2-4-12/) | 焦點不遮蔽(加強) | AAA | 取得焦點的元件連一部分都不能被擋住 |
| [2.4.13](/any/skills/2-4-13/) | 焦點外觀 | AAA | 焦點框夠大、前後對比至少 3:1 |
| [2.5.7](/any/skills/2-5-7/) | 拖曳動作 | AA | 能拖曳的功能，也要能用點擊完成 |
| [2.5.8](/any/skills/2-5-8/) | 目標尺寸(最小) | AA | 點擊目標至少 24×24 CSS 像素 |
| [3.2.6](/any/skills/3-2-6/) | 一致性幫助 | A | 聯絡方式等幫助機制在各頁的相對位置一致 |
| [3.3.7](/any/skills/3-3-7/) | 冗餘輸入 | A | 同一流程中填過的資料，不要求再填一次 |
| [3.3.8](/any/skills/3-3-8/) | 無障礙認證(最小) | AA | 登入不能只靠記憶或解謎 |
| [3.3.9](/any/skills/3-3-9/) | 無障礙認證(加強) | AAA | 同上，例外更少 |

以 AA 為目標的網站，需要處理的是 A 級 2 項加 AA 級 4 項，共 6 項。

### 2.4.11 焦點不遮蔽(最小)

> 當使用者互動介面元件取得鍵盤焦點時，該元件不會因作者所建立的內容而被完全遮蔽。

最常見的違規是**固定在畫面上的頁首、頁尾或 Cookie 橫幅**。用 Tab 往下移動時，焦點跑到了被固定頁首蓋住的連結上，使用者看不到自己在哪裡。

AA 只要求「不被完全遮蔽」，露出一部分就算通過。AAA 的 2.4.12 則要求完全不被遮住。規範的稽核評量碼建議用 `scroll-padding` 處理：

```css
/* 頁首固定高度 4rem，捲動時預留空間 */
html { scroll-padding-top: 4rem; }
```

### 2.5.7 拖曳動作

> 除非拖曳是必要的，或者該功能是由使用者代理程式決定並且未被作者修改，否則所有需要拖曳動作進行操作的功能都可以透過單一指標操作且無需拖曳之方式來實現。

拖曳排序、滑桿、地圖平移、看板卡片移動都會受到影響。「單一指標」指的是點一下就能完成，例如在排序項目旁加上「上移」「下移」按鈕，或讓滑桿可以點擊軌道上的位置。

這一項和 2.1.1 鍵盤不同：鍵盤能操作還不夠，**滑鼠或觸控的使用者**也要能不用拖曳就完成。

### 2.5.8 目標尺寸(最小)

> 除以下條件外，指標輸入目標尺寸至少24乘24 CSS像素

原本 110 年版只有 AAA 的 2.5.5（44×44），這次多了 AA 的 24×24。例外有五種，前端最常用到的是兩種：

- **間距**：目標小於 24px 也可以，只要以每個目標為中心畫直徑 24px 的圓，圓與圓不重疊
- **行內**：句子裡的文字連結不受限制

圖示按鈕、分頁數字、標籤上的「×」是最常不符合的地方。

### 3.2.6 一致性幫助

如果網站在多個頁面都提供幫助機制，例如**人員聯繫方式、聯繫表單、常見問題、聊天機器人**，它們出現的相對順序要一致。

這一項不要求網站一定要提供幫助機制，只要求「有的話，位置要一致」。

### 3.3.7 冗餘輸入

> 之前由使用者輸入或提供給使用者，且必須在相同過程中再次輸入的資訊，屬於下列兩種情況之一：自動填入；提供使用者選擇。

典型例子是結帳流程的「帳單地址同收件地址」。例外有三種：重新輸入是必要的（例如記憶測驗）、為了安全性（例如確認新密碼）、先前的資訊已經失效。

### 3.3.8 無障礙認證(最小)

> 一個認知性功能測試，例如記住一組密碼或者是解決一個謎題，在任何一個認證過程步驟中是不需要的，除非這個步驟提供至少以下一種方式

「認知功能測試」包括記住密碼、抄寫驗證碼、解謎題。AA 有四種例外：提供不考認知的替代方式、提供協助的機制、測試內容是**辨認物件**，或是辨認使用者自己提供的內容。

實務上，「協助的機制」最常見的就是**讓密碼管理工具能自動填入，並允許貼上**。規範也把「阻止以相同格式重新輸入密碼或代碼」列為失敗案例（FA2330801E）。

AAA 的 3.3.9 拿掉了「辨認物件」和「個人內容」這兩個例外，所以「點選所有紅綠燈」這類圖片驗證在 AAA 也不行。

### 2.4.13 焦點外觀（AAA）

焦點框的面積至少等於元件外圍 2 CSS 像素粗的框線，而且同一像素在有焦點和沒焦點時的對比至少 3:1。由瀏覽器決定、作者沒有修改的預設焦點框不在此限。

## 刪除：4.1.1 語法分析

110 年版的 4.1.1 要求 HTML 標籤完整、巢狀正確、屬性不重複、id 不重複。新版保留編號，內文只剩一句「(因過時而刪除。)」，跟 WCAG 2.2 的處理方式一樣。

刪除的原因是現代瀏覽器和輔助科技已經不需要自己剖析 HTML，語法錯誤造成的實際問題，例如名稱或角色讀錯，已經由 4.1.2 名稱、角色和值等準則涵蓋。

<div class="callout" role="note">
  <p class="callout-label"><span aria-hidden="true">⚠</span> 重點</p>
  <p><strong>刪除 4.1.1 不代表 HTML 可以亂寫</strong>。例如重複的 id 仍然會讓 <code>aria-labelledby</code>、<code>&lt;label for&gt;</code> 指錯元素，這時違反的是 1.3.1 或 4.1.2。</p>
</div>

## 修改：26 項文字調整

修改分成三種：意思改變的、範圍或用語更精確的，以及純粹格式調整的。

### 意思有改變

| 編號 | 110 年版 | 115 年版 |
| --- | --- | --- |
| [2.1.1](/any/skills/2-1-1/) 鍵盤 | 特殊目的的網頁（例如遊戲網頁要求在特定時間內完成指定操作）不在此限 | 除非該底層功能所需的輸入是依賴使用者移動的路徑而不僅是端點 |
| [2.5.3](/any/skills/2-5-3/) 標籤名稱 | 該標籤名稱所包含的文字應以可視化呈現 | 該無障礙名稱包含可視的文字 |

**2.1.1 的例外變窄了**。舊版的「特殊目的網頁」範圍模糊，新版和 WCAG 一致：只有手寫簽名、徒手繪圖這類「軌跡本身就是輸入」的功能才能例外，遊戲不再自動豁免。

**2.5.3 的方向反過來了**。舊版讀起來像是「標籤文字要看得到」，新版明確寫出原意：元件的**無障礙名稱**要包含畫面上看得到的文字。例如按鈕顯示「搜尋」，`aria-label` 就不能寫成「送出查詢」，否則語音操作的使用者說「點搜尋」會找不到按鈕。

### 範圍或用語更精確

| 編號 | 調整 |
| --- | --- |
| 1.1.1 非文字內容 | 「請參考指引 4.1」改為「請參考成功準則 4.1.2」 |
| 1.2.1 純音訊與純視訊(預錄) | 「替代內容」改為「時序媒體的替代內容」，句子改寫 |
| 1.2.9 純音訊(現場直播) | 「替代內容」改為「時序媒體替代內容」 |
| 2.2.3 無計時 | 刪除「內容播放時不設時間限制」，改寫為「計時並非內容所呈現的事件或活動之必要組成部分」 |
| 2.2.4 中斷 | 刪除開頭的「內容播放時」，不再限於播放中 |
| 2.4.1 跳過區塊 | 「多頁」改為「多個網頁」 |
| 2.4.5 多種方式 | 「流程」改為「程序」，與用語釋義的「程序(Process)」一致 |
| 2.5.5 目標尺寸 | 名稱改為「目標尺寸(加強)」，和新增的「目標尺寸(最小)」區分 |
| 3.1.3 特殊詞彙 | 「俗語或諺語及行話」改為「慣用語和行話術語」 |
| 3.2.1 焦點 | 「任何元件」改為「任何使用者介面元件」 |

### 格式調整

- **條列加上短標題**：1.1.1、1.4.3、1.4.5、1.4.6、1.4.7、2.2.1、2.2.2、3.3.4、3.3.6 的條列項目前面加了短標題，例如 3.3.4 的「可逆、檢查、確認」，1.4.3 的「大尺寸文字、附帶內容、企業識別標誌」。這和 WCAG 原文的寫法一致，查英文版時比較好對照
- **數字改寫**：例如 1.4.2「3 秒鐘」改為「三秒鐘」，1.4.8「80 個字元」改為「八十個字元」
- **錯字與用字**：「當做」改「當作」、「部份」改「部分」、「脈胳」改「脈絡」、1.3.2「閱讀序列」改「閱讀順序」、1.1.1 與 1.4.7 的「CAPTCHA 驗證」改為「人機驗證(CAPTCHA)」

## 檢測碼：新增準則全部要人工檢查

附件一列了兩種代碼：

| 代碼 | 結尾 | 意思 | A | AA | AAA | 合計 |
| --- | --- | --- | --- | --- | --- | --- |
| 檢測碼 | C | 可用軟體檢測 | 21 | 2 | 5 | 28 |
| 稽核評量碼 | E | 需要人工評估 | 103 | 58 | 55 | 216 |

**28 個檢測碼沒有一個對應到新增的 9 項**，新增準則都只有稽核評量碼，例如：

| 稽核評量碼 | 內容 | 準則 |
| --- | --- | --- |
| FA2241100E | 黏性頁腳或頁首完全遮蔽了焦點元素 | 2.4.11 |
| FA2250700E | 未提供不需拖曳的單一指標操作方式 | 2.5.7 |
| CS2250800E | 使用 min-height 和 min-width 確保足夠的目標間距 | 2.5.8 |
| GN1320600E | 在一致的位置提供「聯繫我們」的鏈接 | 3.2.6 |
| GN1330700E | 在流程中提供上一步驟的數據 | 3.3.7 |
| HM2330800E | 提供適當標記的電子郵件和密碼輸入 | 3.3.8 |
| CS3241200E | 使用 scroll-padding 來消除內容遮蔽 | 2.4.12 |

也就是說，自動檢測工具跑過不代表新增準則都沒問題。改版後送檢之前，這 9 項要排進人工檢查清單。

## 小結

- 對照標準從 WCAG 2.1 換成 2.2，實際準則 78 → 86 項
- 目標 AA 的網站，新增工作集中在 6 項：焦點遮蔽、拖曳替代、24px 目標、一致的幫助位置、不重複輸入、登入不考記憶
- 4.1.1 刪除了，但重複 id 等問題仍會在其他準則被抓到
- 2.1.1 的例外變窄、2.5.3 的意思更明確，舊網站也要回頭檢查
- 新增準則沒有軟體檢測碼，要靠人工檢查
